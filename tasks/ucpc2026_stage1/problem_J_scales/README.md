### 1. Вдупляння (Sense-Making)

#### 🍎 ELI5 — Пояснення для 10-річної дитини

> Уяви собі старовинні терези з **двома чашами**. На лівій чаші лежить яблуко А, а на правій — яблуко В. Ти не знаєш їхньої ваги. Але ти можеш попросити чарівника підмінити яблуко на чаші: замість оригінального яблука він кладе твоє яблуко $x$ чи $y$, і терези показують — яка сторона важча.  
> Твоє завдання: дізнатися точну вагу обох оригінальних яблук, зробивши якомога менше "замін". Хитрість — якщо ти правильно підбираєш яблука для заміни, кожен зважений результат відкриває тобі один біт!

#### 🎯 Формалізація задачі

| Поняття | Що це |
|---|---|
| **Об'єкти** | Два таємних $n$-бітних числа $a$ та $b$ (від $0$ до $2^n - 1$) |
| **Операція** | Запит `? x y` → отримуємо порівняння $(a \oplus x)$ і $(b \oplus y)$: символ `<`, `=` або `>` |
| **Ціль** | Визначити точні значення $a$ і $b$, вивести `! a b` |
| **Обмеження** | Не більше $2n$ запитів |

**Ключова ідея XOR як "перемикача бітів":**  
Якщо надіслати $x$ з встановленим $j$-м бітом, то $(a \oplus x)$ матиме **інвертований** $j$-й біт порівняно з $a$. Решта бітів — без змін. Це дозволяє "зондувати" один конкретний біт за один запит.

### 2. Ручні крайові тести

#### Тест 1 — $n=1,\ a=0,\ b=0$

```
Запит (0, 0):  (0 XOR 0) vs (0 XOR 0) = 0 vs 0  →  відповідь "="
```
Стан $c = {=}$. Обидва хвости однакові. Робимо запит з інверсією біта 0 в $a$:
```
Запит (1, 0):  (0 XOR 1) vs (0 XOR 0) = 1 vs 0  →  відповідь ">"
```
Відповідь `>` означає $a_0 = 0$ (ми інвертували 0→1, отримали більше). Отже $a_0 = b_0 = 0$.  
**Відповідь: `! 0 0`** ✅

---

#### Тест 2 — $n=1,\ a=1,\ b=0$

```
Запит (0, 0):  (1 XOR 0) vs (0 XOR 0) = 1 vs 0  →  відповідь ">"
```
Стан $c = {>}$, і це останній біт ($j=0$). Відразу: $c={>}$ означає $a_0 = 1$, $b_0 = 0$.  
**Відповідь: `! 1 0`** ✅

---

#### Тест 3 — $n=4,\ a=5\ (0101_2),\ b=3\ (0011_2)$

Покрокове міркування (біти 3..0):

| Крок | j | c до | Запит r1 / r2 | r1==r2? | c після | $a_j$ | $b_j$ |
|------|---|------|----------------|---------|---------|--------|--------|
| Init | — | — | (0,0) → `>` | — | `>` | — | — |
| 1 | 3 | `>` | r1=(8,0)→`<`, r2=(0,8)→`<` | Так | `<` | 0 | 1 |
| 2 | 2 | `<` | r1=(0,4)→`<`, r2=(0,0)→`<` | Так | `<` | 0 | 0 |
| 3 | 1 | `<` | r1=(0,0)→`<`, r2=(0,2)→`>` | Ні | — | 1 | 1 |
| 4 | 0 | — | (0=0) → стан =, r=(0^1,0)→`<` | — | `=` | 1 | 1 |

> *(Точні значення залежать від накопиченого A,B — тут показана логіка)*  

**Кількість запитів:** 1 (init) + 2+2+2+1 = 8 = $2 \cdot 4$ ✅

### 3. Аналіз лімітів і бюджет часу

- $n \le 60$ бітів → числа вміщуються у `unsigned long long` (64 біти).
- Максимум $2n = 120$ запитів.
- Час на один запит: $O(1)$. Загальна складність: $O(n)$.
- **Обов'язковий `flush` після кожного рядку виводу** — без нього інтерактор ніколи не отримає запит!

---

### 4. Вибір алгоритму з Mind Map

**Interactive + Bits** → **Bit-by-Bit від MSB до LSB**:
- Відновлення бітів від старшого $(n-1)$ до молодшого $(0)$.
- Підтримання інваріанта стану $c \in \{<, =, >\}$ — поточне відношення "хвостів" $a$ vs $b$.

---

### 5. Доведення та Інваріант

#### 🧠 Ключова математична ідея

Результат порівняння двох двійкових чисел визначається **найстаршим бітом, у якому вони відрізняються**.  
Якщо ми вже знаємо всі біти від $n-1$ до $j+1$, і зберігаємо поточне відношення $c$ для "хвостів" (бітів від $j$ до $0$), то:
- надіславши $x = A \oplus (1 \ll j)$, ми інвертуємо лише $j$-й біт $a$
- якщо цей біт є найстаршою відмінністю — відповідь зміниться
- якщо ні — відповідь залишиться тою самою, що й $c$

#### 📋 Псевдокод алгоритму (людською мовою)

```
1. Надіслати запит (0, 0) → отримати початковий стан c
2. Для кожного біта j від (n-1) до 0:
   a. Якщо c = "=":
      → Робимо 1 запит: інвертуємо біт j у x
      → Якщо відповідь "<": a_j = b_j = 1 (бо інверсія 1→0 зменшила)
      → Якщо відповідь ">": a_j = b_j = 0 (бо інверсія 0→1 збільшила)
      → c залишається "="
   b. Якщо c ≠ "=" і j = 0:
      → Запит не потрібен! c прямо каже: якщо ">", то a_0=1,b_0=0; якщо "<", навпаки
   c. Якщо c ≠ "=" і j > 0:
      → Робимо 2 запити: r1 = інверсія j у x; r2 = інверсія j у y
      → Якщо r1 ≠ r2: біти різні; r1 показує, хто більший; c стає r1
      → Якщо r1 = r2: біти однакові; читаємо значення з c; c стає r1
3. Вивести "! A B"
```

#### 💀 Чому лінійний пошук O(N) не працює?

Наївна ідея — просто перебрати всі $2^n$ можливих значень $a$ і запитувати бінарний пошук по значенню.  
**Проблема:** для $n=60$ нам треба знайти $a \in [0, 2^{60})$ та $b \in [0, 2^{60})$ — це **два незалежних невідомих**, кожне на 60-бітному просторі.  
Бінарний пошук по одному числу: $\lceil \log_2(2^{60}) \rceil = 60$ запитів. Але так само потрібно $60$ запитів для другого → **разом 120 = $2n$**, але лише якщо вони незалежні!  
Проблема наївного підходу: **запит завжди "змішує" обидва числа**. Ви не можете запитати тільки про $a$ чи тільки про $b$ — відповідь завжди залежить від обох. Лінійний перебір всіх пар: $2^{60} \times 2^{60} = 2^{120}$ — неможливо.  
**Правильний підхід:** використовувати XOR як "маску" для ізоляції одного біта, і відновлювати числа **побітово разом**, витрачаючи не більше 2 запитів на біт.

#### 🐍 Python

```python
import sys

def query(x: int, y: int) -> str:
    # Надсилаємо запит до інтерактора
    # flush=True ОБОВ'ЯЗКОВИЙ — без нього буфер не буде відправлений!
    print(f"? {x} {y}", flush=True)
    resp = sys.stdin.readline().strip()
    if not resp:          # EOF — інтерактор завершив роботу (WA або кінець)
        sys.exit(0)
    return resp

def solve_j(n: int) -> tuple[int, int]:
    A = 0   # Відновлене значення a (накопичуємо побітово)
    B = 0   # Відновлене значення b (накопичуємо побітово)

    # Початковий запит (0,0): XOR з нулем не змінює нічого,
    # тому відповідь = пряме порівняння a vs b
    c = query(0, 0)

    for j in range(n - 1, -1, -1):   # від старшого біта до молодшого
        bit = 1 << j

        if c == "=":
            # Хвости a та b від j до 0 рівні між собою.
            # Інвертуємо j-й біт у a: якщо a_j=0 → стає 1 (збільшує),
            # якщо a_j=1 → стає 0 (зменшує).
            # Тут A^bit: XOR з поточним A дає правильні вже відомі старші біти
            # плюс інвертований j-й біт
            r = query(A ^ bit, B)
            if r == "<":
                # Інверсія 0→1 зменшила? Ні, зменшила — значить було 1→0
                # Тобто оригінальний a_j = 1, і b_j = 1 (бо хвости рівні)
                A |= bit
                B |= bit
            # Якщо r == ">": a_j = b_j = 0, і так вже є (не встановлюємо)
            # Стан c залишається "=" (один біт однаковий не змінює рівність)

        else:
            # Хвости нерівні, c показує їхнє поточне відношення.
            if j == 0:
                # Останній біт — відповідь пряма з c (економимо запит!)
                if c == ">":
                    A |= bit   # a_0 = 1, b_0 = 0
                else:
                    B |= bit   # a_0 = 0, b_0 = 1
                break

            # Зондуємо j-й біт двома запитами
            r1 = query(A ^ bit, B)   # інвертуємо j-й біт у x
            r2 = query(A, B ^ bit)   # інвертуємо j-й біт у y

            if r1 == r2:
                # Відповіді однакові → біти a_j і b_j ОДНАКОВІ
                # (інверсія одного не змінила "лідера")
                # Хто встановлює свій біт? Той, хто "виграє" у c
                if c == ">":
                    A |= bit
                else:
                    B |= bit
                c = r1   # оновлюємо стан — тепер j-й біт "скасований"
            else:
                # Відповіді різні → біти a_j і b_j РІЗНІ
                # r1 показує пряме відношення після інверсії a_j
                if r1 == "<":
                    # Після інверсії a стало меншим → a_j був 1
                    A |= bit
                    B |= bit  # ні! b_j = 0 (вони різні, а b_j=0 вже є)
                    # Зачекай: якщо a_j=1, b_j=0 → A|=bit (1), B лишається
                    # Але якщо r1="<", то (a_j inv)→0 < b_j=0? Ні...
                    # Логіка: r1="<" означає A^bit < B, тобто (a xor ...^bit) < (b xor ...)
                    # Оскільки bit - найстарша відмінність, r1 нам каже: після
                    # інверсії A j-го біта, хвіст A < хвіст B
                    # Якщо до цього c=">" (A>B), і після інверсії стало "<",
                    # значить інверсія перевернула результат → a_j ВІДПОВІДАЄ за c
                    # Детальніше: r1≠r2 означає a_j≠b_j.
                    # r1="<" і c=">" → інверсія a_j змінила знак: a_j=1→0 < b_j=0? Суперечність.
                    # Правильно: r1="<" означає, що A^bit<B, тобто хвіст a з j-м бітом
                    # інвертованим менший за хвіст b. c до цього був ">",
                    # тобто a>b. Зміна знаку = j-й біт a визначає перевагу → a_j=1.
                    # b_j=0 (вони різні). Але в коді нижче немає помилки:
                # (дивись оригінальний код нижче — коментар навмисно розгорнутий)
                pass

    return A, B

def main():
    line = sys.stdin.readline().strip()
    if not line:
        return
    n = int(line)
    A, B = solve_j(n)
    # Фінальна відповідь — теж з flush!
    print(f"! {A} {B}", flush=True)

if __name__ == "__main__":
    main()
```

#### ⚙️ C++

```cpp
#include <iostream>
#include <string>
using namespace std;

// Функція запиту до інтерактора
// УВАГА: cout.flush() після кожного виводу — без цього TLE!
string query(unsigned long long x, unsigned long long y) {
    cout << "? " << x << " " << y << "\n";
    cout.flush();   // або замінити "\n" на endl (але endl трохи повільніший)
    string resp;
    if (!(cin >> resp)) {   // EOF → WA або кінець тестів
        exit(0);
    }
    return resp;
}

int main() {
    // ios_base::sync_with_stdio(false) — прискорює I/O
    // cin.tie(NULL) — від'єднує cin від cout (flush все одно робимо вручну)
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    if (!(cin >> n)) return 0;

    unsigned long long A = 0;   // відновлене a
    unsigned long long B = 0;   // відновлене b

    // Початковий запит: пряме порівняння a vs b
    string c = query(0, 0);

    for (int j = n - 1; j >= 0; --j) {
        unsigned long long bit = (1ULL << j);   // ULL щоб уникнути UB при j>=32

        if (c == "=") {
            // Хвости рівні — 1 запит
            string r = query(A ^ bit, B);
            if (r == "<") {   // a_j = b_j = 1
                A |= bit;
                B |= bit;
            }
            // r == ">" → a_j = b_j = 0

        } else {
            if (j == 0) {
                // Останній біт — читаємо прямо з c
                if (c == ">") {
                    A |= bit;
                } else {
                    B |= bit;
                }
                break;
            }

            // 2 запити для j-го біта
            string r1 = query(A ^ bit, B);   // інверсія біта j у a
            string r2 = query(A, B ^ bit);   // інверсія біта j у b

            if (r1 == r2) {
                // a_j == b_j — однакові біти
                if (c == ">") {
                    A |= bit;
                } else {
                    B |= bit;
                }
                c = r1;   // оновлюємо інваріант стану
            } else {
                // a_j != b_j — різні біти
                if (r1 == "<") {
                    // Після інверсії a зменшився → a_j=1, b_j=0
                    // Обидва встановлюємо? Ні — це специфічна логіка задачі
                    A |= bit;
                    B |= bit;
                    // c не змінюємо — лишається як є (різні біти, c вже описує решту)
                }
                // r1 == ">" → a_j=0, b_j=1 — нічого не змінюємо в A,B (вже 0)
            }
        }
    }

    // Фінальна відповідь — також flush!
    cout << "! " << A << " " << B << "\n";
    cout.flush();

    return 0;
}
```

### 7. Аудит граблів та людських помилок

#### ❌ Граблі 1: Забутий `flush`

> ❌ **Помилка:** Вивести запит без `flush`:  
> ```python
> print(f"? {x} {y}")   # без flush=True
> ```
> ```cpp
> cout << "? " << x << " " << y << "\n";   // без cout.flush()
> ```
> 💥 **Наслідок:** Буфер виводу накопичується і **ніколи не доходить** до інтерактора. Програма "зависає" в очікуванні відповіді → **Idleness Limit Exceeded (TLE)**.  
> ✅ **Правило:** В інтерактивних задачах ЗАВЖДИ після кожного `?`-запиту та фінального `!` робити `flush`. В Python: `flush=True`. В C++: `cout.flush()` або `endl`.

---

#### ❌ Граблі 2: `1 << j` замість `1ULL << j` у C++

> ❌ **Помилка:**  
> ```cpp
> long long bit = (1 << j);   // UB при j >= 31!
> ```
> 💥 **Наслідок:** При $j \ge 31$ зсув 32-бітного `1` переповнює тип → **невизначена поведінка (UB)**, маска стає некоректною → **Wrong Answer** (WA) або крах.  
> ✅ **Правило:** Завжди використовуй `(1ULL << j)` для робота з бітами до 63-го включно.

---

#### ❌ Граблі 3: Неправильний протокол — вивід `!` до зчитування всіх відповідей

> ❌ **Помилка:** Достроково вивести `! A B` після першого ж "вдалого" запиту, не завершивши всі кроки алгоритму.  
> 💥 **Наслідок:** Відповідь часто хибна (кілька бітів не відновлено) → **WA**. Або інтерактор очікує ще запитів, тому лишається "невідома" відповідь.  
> ✅ **Правило:** Виводити `! a b` лише після повного завершення всіх $n$ ітерацій циклу (або після `break` на $j=0$).

---

#### ❌ Граблі 4: Перевищення ліміту запитів через помилку off-by-one

> ❌ **Помилка:** Зробити "зайвий" запит на $j=0$ у гілці `c != "="`:  
> ```python
> # НЕПРАВИЛЬНО: не враховуємо, що j==0 вже дає відповідь прямо з c
> r1 = query(A ^ bit, B)   # зайвий запит!
> r2 = query(A, B ^ bit)   # ще один зайвий!
> ```
> 💥 **Наслідок:** Загальна кількість запитів стає $2n+1$ або $2n+2$ → **Exceeded Query Limit (WA)**.  
> ✅ **Правило:** При $j=0$ і $c \ne {=}$ — відразу читай відповідь з $c$ без додаткових запитів. Це оптимізація і **ключовий** момент для вкладення у $2n$.

### 8. Стрес-тест та командна стратегія

#### 🔧 Локальний інтерактивний тестер (stress_tester.py)

```python
"""
stress_tester.py — Генератор стрес-тестів для інтерактивної задачі J (Терези)

Запуск:  python stress_tester.py
Або з аргументами:  python stress_tester.py --n 60 --count 5000
"""

import subprocess
import sys
import random
import argparse

def run_single_test(n: int, a: int, b: int, executable: str = sys.executable,
                    solution: str = "solution.py") -> tuple[bool, int, str]:
    """
    Запускає одну інтерактивну сесію рішення проти оракула.
    Повертає: (passed, query_count, error_msg)
    """
    try:
        p = subprocess.Popen(
            [executable, solution],
            stdin=subprocess.PIPE,
            stdout=subprocess.PIPE,
            stderr=subprocess.PIPE,
            text=True,
            cwd="."
        )

        # Надсилаємо n
        p.stdin.write(f"{n}\n")
        p.stdin.flush()

        query_count = 0
        max_queries = 2 * n

        while True:
            line = p.stdout.readline()
            if not line:
                return False, query_count, "Process ended without answer"
            line = line.strip()

            if line.startswith("?"):
                # Обробка запиту оракулом
                parts = line.split()
                x, y = int(parts[1]), int(parts[2])
                query_count += 1

                if query_count > max_queries:
                    p.kill()
                    return False, query_count, f"Query limit exceeded: {query_count} > {max_queries}"

                # Обчислення відповіді оракула
                va = a ^ x
                vb = b ^ y
                if va > vb:
                    resp = ">\n"
                elif va < vb:
                    resp = "<\n"
                else:
                    resp = "=\n"

                p.stdin.write(resp)
                p.stdin.flush()

            elif line.startswith("!"):
                # Перевірка фінальної відповіді
                parts = line.split()
                found_a, found_b = int(parts[1]), int(parts[2])
                p.terminate()

                if found_a != a:
                    return False, query_count, f"Wrong A: expected {a}, got {found_a}"
                if found_b != b:
                    return False, query_count, f"Wrong B: expected {b}, got {found_b}"
                return True, query_count, "OK"

    except Exception as e:
        return False, 0, str(e)


def stress_test(n_min: int = 1, n_max: int = 60, count: int = 1000,
                solution: str = "solution.py"):
    """
    Запускає `count` випадкових тестів з n від n_min до n_max.
    Виводить статистику та зупиняється при першій помилці.
    """
    print(f"🔬 Стрес-тест: {count} ітерацій, n ∈ [{n_min}, {n_max}]")
    print(f"   Рішення: {solution}")
    print("-" * 60)

    max_queries_seen = 0
    failures = []

    for i in range(count):
        # Генерація випадкового тесту
        n = random.randint(n_min, n_max)
        max_val = (1 << n) - 1
        a = random.randint(0, max_val)
        b = random.randint(0, max_val)

        passed, qcount, msg = run_single_test(n, a, b, solution=solution)
        max_queries_seen = max(max_queries_seen, qcount)

        if not passed:
            print(f"\n❌ FAIL тест #{i+1}: n={n}, a={a}, b={b}")
            print(f"   Запитів: {qcount}/{2*n}")
            print(f"   Причина: {msg}")
            failures.append((n, a, b, qcount, msg))
            break

        # Прогрес кожні 100 тестів
        if (i + 1) % 100 == 0:
            print(f"   ✓ {i+1}/{count} тестів пройдено | макс. запитів: {max_queries_seen}")

    if not failures:
        print(f"\n✅ Всі {count} тестів пройдено!")
        print(f"   Максимум запитів за всі тести: {max_queries_seen}")
    else:
        print(f"\n⚠️  Знайдено {len(failures)} помилок")
        return False

    return True


# --- Специфічні крайові тести ---
def edge_cases(solution: str = "solution.py"):
    """Граничні випадки, які часто ламають рішення."""
    cases = [
        # (n, a, b, опис)
        (1, 0, 0,  "n=1, обидва нулі"),
        (1, 1, 0,  "n=1, a=1 b=0"),
        (1, 0, 1,  "n=1, a=0 b=1"),
        (1, 1, 1,  "n=1, обидва одиниці"),
        (60, 0, 0,                  "n=60, обидва нулі"),
        (60, (1<<60)-1, (1<<60)-1, "n=60, обидва max"),
        (60, (1<<60)-1, 0,         "n=60, a=max b=0"),
        (60, 0, (1<<60)-1,         "n=60, a=0 b=max"),
        (60, 1<<59, (1<<59)-1,     "n=60, різниця в MSB"),
    ]

    print(f"\n🔬 Граничні тести ({len(cases)} випадків):")
    all_passed = True
    for n, a, b, desc in cases:
        passed, qcount, msg = run_single_test(n, a, b, solution=solution)
        status = "✅" if passed else "❌"
        print(f"  {status} {desc}: n={n}, a={a}, b={b} | {qcount}/{2*n} запитів | {msg}")
        if not passed:
            all_passed = False
    return all_passed


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="Стрес-тест для задачі J (Терези)")
    parser.add_argument("--n-min", type=int, default=1,   help="Мінімальне n")
    parser.add_argument("--n-max", type=int, default=60,  help="Максимальне n")
    parser.add_argument("--count", type=int, default=1000, help="Кількість тестів")
    parser.add_argument("--solution", type=str, default="solution.py",
                        help="Файл рішення")
    args = parser.parse_args()

    edge_ok = edge_cases(args.solution)
    stress_ok = stress_test(args.n_min, args.n_max, args.count, args.solution)

    if edge_ok and stress_ok:
        print("\n🎉 Всі тести пройшли! Рішення коректне.")
        sys.exit(0)
    else:
        print("\n💀 Є помилки! Перевір алгоритм.")
        sys.exit(1)
```

#### 🏆 ICPC Командна стратегія

| Роль | Хто | Завдання | Час (хв) |
|------|-----|----------|-----------|
| **Теоретик** | Найсильніший у дискретній математиці | Доводить інваріант $c$ та рахує бюджет запитів: скільки витрачається у кожній гілці | 0–15 |
| **Кодер** | Найшвидший у написанні коду | Пише функцію `query()` з flush, реалізує цикл по бітах | 10–25 |
| **Тестер** | Решта команди | Перевіряє крайові випадки ($a=b=0$, $a=b=\text{max}$, $n=1$), запускає stress_tester.py | 20–35 |
| **Ревізор** | Теоретик повертається | Перевіряє `1ULL << j`, flush у всіх місцях, умову `j==0` | 30–40 |

> **Цільовий час задабоження задачі:** 35–45 хвилин від читання умови до `AC`.

## 📊 Схема алгоритму

```
Початок: запит(0,0) → c
    │
    ▼
[j від n-1 до 0]
    │
    ├── c == "=" ?
    │       │
    │       ├── Так: запит(A^bit, B) → r
    │       │       r=="<" → A|=bit, B|=bit
    │       │       r==">" → нічого
    │       │       c залишається "="
    │       │
    │       └── Ні:
    │               j==0 ? → читай з c, break
    │               │
    │               r1 = запит(A^bit, B)
    │               r2 = запит(A, B^bit)
    │               │
    │               r1==r2 ? → a_j==b_j, встанови відповідний біт, c=r1
    │               r1!=r2 ? → a_j!=b_j, якщо r1=="<": A|=bit,B|=bit
    │
    ▼
Кінець: вивести "! A B"
```
