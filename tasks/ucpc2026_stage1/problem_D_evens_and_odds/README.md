### 1. Вдупляння (Sense-Making)

#### 🍎 ELI5 — для 10-річної дитини

> Уяви **терези** з двома чашами.  
> **Ліва чаша** — кидаємо непарні цифри, що стоять на парних позиціях числа (позиція 0 = одиниці, позиція 2 = сотні, ...).  
> **Права чаша** — кидаємо парні цифри, що стоять на непарних позиціях (позиція 1 = десятки, позиція 3 = тисячі, ...).  
>
> Терези «збалансовані», якщо обидві чаші важать однаково.  
>
> Тобі дали число $N$ — терези вже трохи перекошені. Ти можеш **дописати цифри справа** — це як класти **гирки** на певні позиції. Але увага: кожна нова гирка справа **зсуває вліво** всі старі гирки (змінює позиції!).  
>
> **Задача:** дописати якомога менше цифр, щоб терези врівноважились. При рівній кількості — обрати найменше можливе число.

#### 📦 Об'єкти | Операції | Ціль

| Що | Опис |
|----|------|
| **Об'єкти** | Число $N$ (до $10^5$ цифр), індекс позиції від `0` (справа), парність цифри та позиції |
| **Операції** | Дописати суфікс довжини $k$ ($k \ge 0$) до $N$ |
| **Ціль** | Отримати $M$ збалансованим: $\sum_{\text{pos парна}} d_{\text{непарна}} = \sum_{\text{pos непарна}} d_{\text{парна}}$, де $M$ — мінімальне |

**Формальне визначення збалансованості:**

$$\text{balanced}(S) \iff \sum_{\substack{i \text{ — парна позиція} \\ S_i \text{ — непарна цифра}}} S_i \;=\; \sum_{\substack{i \text{ — непарна позиція} \\ S_i \text{ — парна цифра}}} S_i$$

де позиції рахуються **справа наліво** (позиція `0` = наймолодший розряд).

### 2. Ручні крайові тести

#### Тест 1: $N = 4$
**Вхід:** `4`  
**Покрокове міркування:**
- Цифра `4`, позиція `0` (парна) → `4` парна → не потрапляє до лівої чаші (потрібна **непарна** на парній)
- Ліва чаша = 0, Права чаша = 0 → збалансовано!

**Відповідь:** `4` ✅

---

#### Тест 2: $N = 5$
**Вхід:** `5`  
**Покрокове міркування:**
- Цифра `5`, позиція `0` (парна) → `5` непарна → ліва чаша = `5`
- Права чаша = 0 → дисбаланс $T = -5$ (треба поповнити праву або зменшити ліву)
- Спробуємо $k=1$: дописуємо 1 цифру. Вона займе позицію `0`, стара `5` перейде на позицію `1`.
  - $k$ непарне → стара `5` тепер на позиції `1` (непарна), але `5` непарна → не до правої чаші → $D_1 = 0$
  - Потрібно від нової цифри на позиції `0`: нова непарна на парній = нова_цифра якщо непарна. Потрібно $T=0$ від блоку.
  - Цифра `0` (парна на позиції `0`) → внесок = 0. Рівновага! Мінімальна цифра = `0`.

**Відповідь:** `50` ✅

---

#### Тест 3: $N = 2468$
**Вхід:** `2468`  
**Покрокове міркування:**
- Позиції (справа наліво): `8`→pos0, `6`→pos1, `4`→pos2, `2`→pos3
- Ліва чаша (непарні цифри на парних позиціях): нема непарних → 0
- Права чаша (парні цифри на непарних позиціях): `6`(pos1) + `2`(pos3) = 8 → $D_0 = 0 - 8 = -8$
- При $k=0$: дисбаланс. При $k=1,2,\ldots$ шукаємо перше $k$, де умова виконується.
- Відповідь: `2468309` — блок `309` компенсує дисбаланс.

**Відповідь:** `2468309` ✅

### 5. Доведення та Інваріант

#### 🧠 Ключова ідея: зсув позицій

Коли дописуємо блок довжини $k$, кожна цифра числа $N$ зсувається на $k$ позицій вліво:
- Якщо $k$ **парне** → парність позицій цифр $N$ **не змінюється** → їх внесок = $D_0$  
- Якщо $k$ **непарне** → парність позицій **інвертується** → їх внесок = $D_1$

Де:
$$D_0 = \sum_{\substack{i \text{ парна}\\N_i \text{ непарна}}} N_i \;-\; \sum_{\substack{i \text{ непарна}\\N_i \text{ парна}}} N_i$$
$$D_1 = \sum_{\substack{i \text{ непарна}\\N_i \text{ непарна}}} N_i \;-\; \sum_{\substack{i \text{ парна}\\N_i \text{ парна}}} N_i$$

Блок з $k$ цифр має компенсувати: $T = -D_{k \bmod 2}$

#### 📝 Псевдокод (4 кроки)

```
1. ОБЧИСЛИ D0 і D1 (внески N без суфікса та з інвертованими позиціями)
   → проходимо по цифрах N справа наліво, рахуємо два акумулятори

2. ЯКЩО D0 = 0 → повернути N (вже збалансовано)

3. ДЛЯ k = 1, 2, 3, ... ДО |N|+120:
   а. T = -D0 (якщо k парне) або -D1 (якщо k непарне)
   б. e = ⌈k/2⌉ парних позицій у блоці, o = ⌊k/2⌋ непарних
   в. ПЕРЕВІР чи існує розкладка: x - y = T,
      де x ∈ {суми непарних цифр на парних позиціях блоку},
          y ∈ {суми парних цифр на непарних позиціях блоку}
   г. ЯКЩО існує → перейти до кроку 4

4. ЖАДІБНО будуй блок зліва направо:
   для кожної позиції pos (від найстаршої до наймолодшої):
     вибирай мінімальну цифру d ∈ [0..9],
     яка не «вбиває» можливість добудувати решту блоку
   → повернути N + блок
```

#### ❌ Чому наївний перебір усіх суфіксів ламається

Наївний підхід: перебираємо всі числа від $N+1$ до $\infty$, перевіряємо кожне.

**Де він задихається:**
1. **TLE:** При $|N| = 10^5$ цифр навіть перебір $k$ від 1 до 200 із перебором усіх $10^k$ суфіксів = $10^{200}$ операцій — нереально.
2. **Неправильне розуміння «мінімуму»:** «Мінімальне число» ≠ «мінімальний суфікс» — потрібна лексикографічна жадібність порозрядно.
3. **Ігнорування інваріанту зсуву:** Без математичного аналізу $D_0/D_1$ не зрозуміло, коли $k$ парне vs непарне.

```python
import sys

def check_balanced(s: str) -> int:
    """Повертає 0 якщо рядок збалансований, інакше ненульове значення."""
    s_rev = s[::-1]
    contrib = 0
    for pos, ch in enumerate(s_rev):
        d = int(ch)
        if pos % 2 == 0:
            if d % 2 == 1:
                contrib += d      # непарна цифра на парній позиції → +
        else:
            if d % 2 == 0:
                contrib -= d      # парна цифра на непарній позиції → -
    return contrib

def can_solve(rem_e: int, rem_o: int, T: int) -> bool:
    """
    Чи можна з rem_e парних і rem_o непарних позицій, що залишились,
    набрати сумарний баланс рівно T?
    x - y = T, де x ∈ [p, 9*E_p], y ∈ [0, 8*rem_o], x ≡ T (mod 2)
    """
    p = T % 2
    # E_p = найбільша кількість парних позицій потрібної парності
    if p == 0:
        E_p = rem_e if rem_e % 2 == 0 else rem_e - 1
    else:
        E_p = rem_e if rem_e % 2 == 1 else rem_e - 1

    if E_p < p:
        if p == 1 or rem_e < 0:
            return False

    low_x = p
    high_x = 9 * E_p
    low_req = max(T, low_x)       # x мусить бути >= T (бо y >= 0)
    high_req = min(T + 8 * rem_o, high_x)  # x мусить бути <= T+8o (бо y <= 8o)
    return low_req <= high_req

def solve_d(N: str) -> str:
    N = N.strip()
    if not N:
        return ""

    N_rev = N[::-1]

    # Обчислення D0 і D1 (внески N при парному та непарному зсуві)
    d0 = 0  # k парне: позиції не змінюються
    d1 = 0  # k непарне: позиції інвертуються (pos → pos+1)
    for pos, ch in enumerate(N_rev):
        d = int(ch)
        # D0: оригінальні позиції
        if pos % 2 == 0:
            if d % 2 == 1: d0 += d
        else:
            if d % 2 == 0: d0 -= d
        # D1: зсунуті позиції (pos+1)
        if (pos + 1) % 2 == 0:
            if d % 2 == 1: d1 += d
        else:
            if d % 2 == 0: d1 -= d

    # Якщо вже збалансовано
    if d0 == 0:
        return N

    max_k = len(N) + 120
    for k in range(1, max_k):
        shift_parity = k % 2
        T = -d0 if shift_parity == 0 else -d1  # потрібний баланс від блоку
        e = (k + 1) // 2  # парних позицій у блоці (pos 0,2,4,...)
        o = k // 2        # непарних позицій у блоці (pos 1,3,5,...)

        if can_solve(e, o, T):
            # Жадібна побудова блоку: перебираємо позиції від найстаршої до наймолодшої
            block = []
            curr_T = T
            cur_e = e
            cur_o = o
            for pos in range(k - 1, -1, -1):
                is_even = (pos % 2 == 0)
                next_e = cur_e - (1 if is_even else 0)
                next_o = cur_o - (1 if not is_even else 0)

                for d in range(10):  # мінімальна цифра першою
                    if is_even:
                        add = d if d % 2 == 1 else 0   # непарна на парній → +
                        nxt_T = curr_T - add
                    else:
                        sub = d if d % 2 == 0 else 0   # парна на непарній → +y → -T
                        nxt_T = curr_T + sub
                    if can_solve(next_e, next_o, nxt_T):
                        block.append(str(d))
                        curr_T = nxt_T
                        cur_e = next_e
                        cur_o = next_o
                        break
            return N + "".join(block)
    return N

def main():
    lines = sys.stdin.read().split()
    for token in lines:
        print(solve_d(token))

if __name__ == "__main__":
    main()
```

#include <iostream>
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

/**
 * Перевіряє: чи можна з rem_e парних і rem_o непарних позицій набрати баланс T?
 * Математика: x - y = T, x ≡ T (mod 2), x ∈ [p, 9*E_p], y ∈ [0, 8*rem_o]
 */
bool can_solve(int rem_e, int rem_o, int T) {
    int p = (T % 2 + 2) % 2;  // завжди невід'ємне (C++ % може бути від'ємним)
    int E_p;
    if (p == 0) {
        E_p = (rem_e % 2 == 0) ? rem_e : rem_e - 1;
    } else {
        E_p = (rem_e % 2 == 1) ? rem_e : rem_e - 1;
    }

    if (E_p < p) {
        if (p == 1 || rem_e < 0) return false;
    }

    int low_x  = p;
    int high_x = 9 * E_p;
    int low_req  = max(T, low_x);            // x >= T (бо y >= 0)
    int high_req = min(T + 8 * rem_o, high_x); // x <= T+8o (бо y <= 8o)
    return low_req <= high_req;
}

string solve_d(const string& N) {
    if (N.empty()) return "";

    // Розворот для зручної індексації позицій справа наліво
    string N_rev = N;
    reverse(N_rev.begin(), N_rev.end());

    // Обчислення D0 (k парне) і D1 (k непарне)
    int d0 = 0, d1 = 0;
    for (size_t pos = 0; pos < N_rev.size(); ++pos) {
        int d = N_rev[pos] - '0';
        // D0: оригінальні позиції
        if (pos % 2 == 0) { if (d % 2 == 1) d0 += d; }
        else               { if (d % 2 == 0) d0 -= d; }
        // D1: зсунуті позиції (pos+1)
        if ((pos + 1) % 2 == 0) { if (d % 2 == 1) d1 += d; }
        else                     { if (d % 2 == 0) d1 -= d; }
    }

    // Вже збалансовано
    if (d0 == 0) return N;

    int max_k = (int)N.size() + 120;
    for (int k = 1; k < max_k; ++k) {
        int T = (k % 2 == 0) ? -d0 : -d1;  // потрібний баланс від блоку
        int e = (k + 1) / 2;                // парних позицій у блоці
        int o = k / 2;                      // непарних позицій у блоці

        if (can_solve(e, o, T)) {
            string block;
            int curr_T = T, cur_e = e, cur_o = o;

            // Жадібна побудова: від найстаршої позиції до наймолодшої
            for (int pos = k - 1; pos >= 0; --pos) {
                bool is_even = (pos % 2 == 0);
                int next_e = cur_e - (is_even ? 1 : 0);
                int next_o = cur_o - (!is_even ? 1 : 0);

                for (int d = 0; d < 10; ++d) {
                    int nxt_T = curr_T;
                    if (is_even) {
                        int add = (d % 2 == 1) ? d : 0;  // непарна на парній → +
                        nxt_T -= add;
                    } else {
                        int sub = (d % 2 == 0) ? d : 0;  // парна на непарній
                        nxt_T += sub;
                    }
                    if (can_solve(next_e, next_o, nxt_T)) {
                        block.push_back('0' + d);
                        curr_T = nxt_T; cur_e = next_e; cur_o = next_o;
                        break;
                    }
                }
            }
            return N + block;
        }
    }
    return N;
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);
    string s;
    while (cin >> s) {
        cout << solve_d(s) << "\n";
    }
    return 0;
}

### 7. Аудит граблів та людських помилок

#### ❌ Граблі 1: Забули інверсію при непарному $k$

> **❌ Помилка:** При будь-якому $k$ використовуємо один і той самий внесок $D_0$ від $N$.  
> **💥 Наслідок:** WA — при непарному $k$ всі старі цифри змінюють парність позиції, тому реальний внесок від $N$ = $D_1 \ne D_0$.  
> **✅ Правило:** Завжди: `T = -D0 if k%2==0 else -D1`. Обчислюй обидва значення наперед.

---

#### ❌ Граблі 2: Плутанина з орієнтацією позицій

> **❌ Помилка:** Вважаємо, що позиція `0` — це **перша цифра зліва** (найстарший розряд).  
> **💥 Наслідок:** WA на всіх тестах, де кількість цифр непарна, — всі парності перевернуті.  
> **✅ Правило:** Позиція `0` = найправіша цифра (одиниці). Завжди працюй з `N[::-1]` або `N_rev`.

---

#### ❌ Граблі 3: Від'ємне взяття за модулем у C++

> **❌ Помилка:** `T % 2` в C++ при від'ємному `T` дає від'ємний залишок (`-5 % 2 == -1`).  
> **💥 Наслідок:** WA — `p` стає `-1`, умова `E_p < p` ламається, `can_solve` повертає неправильний результат.  
> **✅ Правило:** Використовуй `(T % 2 + 2) % 2` або `abs(T % 2)` для гарантовано невід'ємного залишку.

---

#### ❌ Граблі 4: Неправильна парність $T$ при побудові блоку

> **❌ Помилка:** Підбираємо мінімальну цифру без врахування того, що $x \equiv T \pmod{2}$ — тобто сума непарних цифр на парних позиціях мусить мати ту ж парність, що й $T$.  
> **💥 Наслідок:** WA — навіть якщо `can_solve` сказав «так» для всього блоку, жадібна побудова заходить у глухий кут наприкінці (остання позиція не може набрати потрібну суму).  
> **✅ Правило:** Завжди виклик `can_solve(next_e, next_o, nxt_T)` після кожного вибору цифри — це гарантує, що залишок завжди досяжний.

### 8. Стрес-тест та командна стратегія

#### 🐛 Генератор для стрес-тесту

Збережи як `stress_tester.py` поряд із `solution.py`:

```python
"""
stress_tester.py — стрес-тест для Problem D: Evens and Odds
Порівнює швидкий розв'язок (solution.py) із brute-force перевіркою.
"""
import random
import subprocess
import sys
import os

SOLUTION = os.path.join(os.path.dirname(__file__), "solution.py")

def check_balanced(s: str) -> bool:
    """Перевіряємо, чи рядок s є збалансованим."""
    s_rev = s[::-1]
    contrib = 0
    for pos, ch in enumerate(s_rev):
        d = int(ch)
        if pos % 2 == 0:
            if d % 2 == 1: contrib += d
        else:
            if d % 2 == 0: contrib -= d
    return contrib == 0

def brute_force(N: str) -> str:
    """
    Brute-force: знаходимо мінімальний збалансований M >= N
    шляхом послідовного перебору рядків.
    Тільки для малих N (до 6 цифр)!
    """
    # Спробуємо суфікси довжиною 0..12
    for k in range(13):
        if k == 0:
            if check_balanced(N):
                return N
        else:
            # Перебираємо всі суфікси довжини k лексикографічно
            from itertools import product
            for digits in product("0123456789", repeat=k):
                candidate = N + "".join(digits)
                if check_balanced(candidate):
                    return candidate
    return N  # не знайшли (не повинно статися)

def run_solution(N: str) -> str:
    """Запускає solution.py і повертає відповідь."""
    p = subprocess.run(
        [sys.executable, SOLUTION],
        input=N, text=True, capture_output=True
    )
    return p.stdout.strip()

def random_number(max_digits=5) -> str:
    """Генерує випадкове число від 1 до max_digits цифр."""
    length = random.randint(1, max_digits)
    first = random.randint(1, 9)
    rest = [random.randint(0, 9) for _ in range(length - 1)]
    return str(first) + "".join(map(str, rest))

def stress_test(n_tests=500, seed=42):
    random.seed(seed)
    print(f"Запускаємо {n_tests} стрес-тестів (числа до 5 цифр)...")
    for i in range(n_tests):
        N = random_number(max_digits=5)
        expected = brute_force(N)
        got = run_solution(N)
        if got != expected:
            print(f"[FAIL] N={N}: очікувалось={expected}, отримано={got}")
            return
        if not check_balanced(got):
            print(f"[FAIL] N={N}: відповідь {got} не збалансована!")
            return
        if i % 50 == 0:
            print(f"  Пройдено {i}/{n_tests} тестів...")
    print("✅ Всі стрес-тести пройдено!")

if __name__ == "__main__":
    stress_test()
```

> [!TIP]
> Brute-force у стрес-тесті використовує `itertools.product` — він стає дуже повільним при `max_digits > 6`. Для більших чисел використовуй лише перевірку `check_balanced` без перебору суфіксів.
