# Problem E: Чотири числа (Four Numbers)
**Турнір:** UCPC 2026. Stage I (Офіційний розбір: Сторінка 6)  
**Теги:** `Meet-in-the-Middle`, `Two Pointers`, `Sorting`, `Arrays`, `O(N^2 log N)`  
**Складність:** Medium  

---

## ⚡ 8-Кроковий Золотий Стандарт Розбору

### 1. Вдупляння (Sense-Making)
Дано масив із $n$ цілих чисел $a_1, a_2, \dots, a_n$ та граничне значення $m$.  
Потрібно вибрати мультимножину з **чотирьох індексів** (дозволяється брати один і той самий елемент кілька разів, від $1$ до $4$ разів), тобто четвірку $\{i, j, k, t\}$, сума елементів якої не перевищує $m$:
$$a_i + a_j + a_k + a_t \le m$$
Серед усіх таких четвірок треба **максимізувати** цю суму. Якщо жодна четвірка не дає суму $\le m$, вивести `-1`.

---

### 2. Ручні крайові тести
1. **$n = 1, a = [5], m = 20$:**  
   Четвірка може брати єдиний елемент 4 рази: $5 + 5 + 5 + 5 = 20 \le 20$. Відповідь: $20$.
2. **$n = 1, a = [5], m = 19$:**  
   Єдина сума $20 > 19$. Жодна четвірка не влазить. Відповідь: `-1`.
3. **Від'ємні числа та нуль:** $a = [-10, 2], m = -5$.  
   Четвірка $[-10, 2, 2, 2]$ дає суму $-4 > -5$.  
   Четвірка $[-10, -10, 2, 2]$ дає суму $-16 \le -5$.  
   Відповідь може бути від'ємною, тому не можна використовувати `0` чи `-1` як фіктивний сторож!

---

### 3. Аналіз лімітів і бюджет часу
- $n \le 3000$.
- $a_i \in [-10^9, 10^9]$, $m \in [-4 \cdot 10^{18}, 4 \cdot 10^{18}]$.
- Наївний перебір 4 циклів: $O(n^4) \approx 3000^4 \approx 8 \cdot 10^{13} \implies$ TLE.
- Перебір трьох циклів з бінарним пошуком четвертого: $O(n^3 \log n) \approx 2.7 \cdot 10^{10} \implies$ TLE.
- **Оптимальний підхід (Meet-in-the-Middle):**  
  Розбиваємо 4 елементи на дві пари по 2 елементи:
  - Кількість парних сум $s = \frac{n(n+1)}{2} \approx \frac{3000 \times 3001}{2} \approx 4.5 \cdot 10^6$.
  - Сортування парних сум: $O(n^2 \log(n^2)) = O(n^2 \log n)$.
  - Пошук двома вказівниками: $O(n^2)$.
  - Загальний час: $\approx 4.5 \cdot 10^6 \times 22$ операцій, що вкладається в ліміт часу.

### 4. Вибір алгоритму з Mind Map
- [docs/ALGORITHM_DECISION_TREE.md](../../docs/ALGORITHM_DECISION_TREE.md) $\to$ **Two Pointers & Meet-in-the-Middle**:
  - Генерація всіх $O(n^2)$ попарних сум $p = a_i + a_j$.
  - Сортування масиву $p$.
  - Метод двох вказівників (Left & Right) для знаходження $\max(p_l + p_r \le m)$.

### 5. Доведення та Інваріант
Будь-яку четвірку можна представити як суму двох пар: $(a_i + a_j) + (a_k + a_t)$.  
Нехай $p_1 \le p_2 \le \dots \le p_s$ — відсортований масив усіх $s$ попарних сум.  
Задача зводиться до знаходження пари індексів $(l, r)$, таких що $l \le r$ і $p_l + p_r \le m$, з максимальною сумою.

**Алгоритм двох вказівників:**
Починаємо з $l = 0, r = s - 1$.
1. Якщо $p_l + p_r \le m$:  
   Поточна сума є кандидатом на максимум. Для фіксованого $l$ жодна пара з більшим індексом, ніж $r$, не підходить (бо масив відсортований, а всі елементи правіше $r$ уже давали суму $> m$). Тому ми фіксуємо найкращий результат для поточного $l$ і рухаємо лівий вказівник управо: $l \leftarrow l + 1$.
2. Якщо $p_l + p_r > m$:  
   Сума занадто велика. Оскільки $p_l$ — найменший з доступних елементів, навіть з ним сума перевищує $m$. Отже, поточний елемент $p_r$ взагалі не може утворити допустиму пару з жодним елементом $\ge p_l$. Зменшуємо правий вказівник: $r \leftarrow r - 1$.

### 6. Двомовний код (C++20 та Python 3.12)
- C++20: [solution.cpp](file:///C:/project/super-algo/tasks/ucpc2026_stage1/problem_E_four_numbers/solution.cpp)
- Python 3.12: [solution.py](file:///C:/project/super-algo/tasks/ucpc2026_stage1/problem_E_four_numbers/solution.py)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n;
    long long m;
    if (!(cin >> n >> m)) return 0;

    vector<long long> a(n);
    for (int i = 0; i < n; ++i) cin >> a[i];

    // 1. Усі попарні суми (до 4.5 * 10^6)
    vector<long long> p;
    p.reserve(n * (n + 1LL) / 2);
    for (int i = 0; i < n; ++i) {
        for (int j = i; j < n; ++j) {
            p.push_back(a[i] + a[j]);
        }
    }

    // 2. Сортування
    sort(p.begin(), p.end());

    // 3. Два вказівники
    int l = 0, r = (int)p.size() - 1;
    bool found = false;
    long long best_sum = LLONG_MIN;

    while (l <= r) {
        long long cur = p[l] + p[r];
        if (cur <= m) {
            if (!found || cur > best_sum) {
                best_sum = cur;
                found = true;
            }
            l++;
        } else {
            r--;
        }
    }

    if (found) cout << best_sum << "\n";
    else cout << -1 << "\n";

    return 0;
}
```

### 7. Аудит граблів та людських помилок
- ❌ **Сторожове значення -1:** Оскільки числа можуть бути від'ємними, оптимальна сума може бути, наприклад, $-10$ або навіть $-1$. Якщо перевіряти `if (ans == -1)`, ми переплутаємо валідну суму $-1$ з випадком, коли розв'язку немає! Потрібно тримати явний булевий прапорець `bool found = false`.
- ❌ **Переповнення 32-бітних чисел:** Сума 4 чисел до $10^9$ досягає $4 \cdot 10^9$, що не вміщується в стандартний знакововий 32-бітний `int`. Потрібно суворо використовувати `long long` у C++.
- ❌ **Використання `std::set` для збереження сум:** Дерево пошуку має величезний оверхед по пам'яті (32 байти на вузол) та кеш-промахи, що викличе Memory Limit Exceeded або TLE. Потрібен простий плаский масив `std::vector<long long>`.

### 8. Стрес-тест та командна стратегія
- **ICPC Тактика:**

  - Тестер перевіряє крайній випадок: всі числа від'ємні та $m < 4 \min(a_i)$.
