**Складність:** Easy-Medium

## ⚡ 8-Кроковий Золотий Стандарт Розбору

### 1. Вдупляння (Sense-Making)
Дано рядок, що містить дужки різних типів: круглі `()`, квадратні `[]` та фігурні `{}`.
Потрібно перевірити, чи є ця послідовність дужок **правильною** (Regular Bracket Sequence — RBS):
1. Кожна відкривна дужка повинна закриватися відповідною дужкою того ж типу.
2. Дужки повинні закриватися у правильному порядку вкладеності (наприклад, `([)]` є хибним, а `[()]` — правильним).
3. Порожній рядок вважається правильним.

**Що вивести:**  
`YES`, якщо дужкова послідовність правильна, і `NO` в іншому випадку.

---

### 2. Ручні крайові тести
1. **Базовий коректний вкладений:**  
   Вхід: `([{}])` $\implies$ Вихід: `YES`.
2. **Перехресне перекриття (граблі для наївних лічильників):**  
   Вхід: `([)]` $\implies$ Вихід: `NO`. Кількість відкривних і закривних однакова, але порядок порушено.
3. **Зайва закривна або відкривна:**  
   Вхід: `)` $\implies$ Вихід: `NO`. Стек спорожнів раніше, ніж очікувалось.  
   Вхід: `(` $\implies$ Вихід: `NO`. Стек не спорожнів наприкінці.

---

### 3. Аналіз лімітів і бюджет часу
- Довжина рядка $|S| \le 10^5$.
- Кількість запитів $T \ge 1$.
- Ліміт часу: $1.0$ секунда ($\approx 10^8$ операцій).
- Необхідна лінійна складність: **$O(|S|)$** на перевірку одного рядка.
- Пам'ять: $O(|S|)$ для стека відкривних дужок.

### 4. Вибір алгоритму з Mind Map
- [docs/ALGORITHM_DECISION_TREE.md](../../docs/ALGORITHM_DECISION_TREE.md) $\to$ **Data Structures** $\to$ **LIFO Stack $O(N)$**:
  - Відкривні символи кладемо в стек.
  - При зустрічі закривного символу знімаємо вершину стека та перевіряємо відповідність типів.
  - Наприкінці перевіряємо умову `stack.empty()`.

---

### 5. Доведення та Інваріант
**Інваріант стека LIFO:**  
У будь-який момент часу $i$ стек містить суфікс ще незакритих відкривних дужок префікса $S[0..i]$. Кожна закривна дужка $S[i]$ зобов'язана паруватися з **останньою ще незакритою відкривною дужкою**, яка знаходиться на самій вершині стека. Якщо тип не збігається або стек порожній — правильність порушено. Якщо після обробки всього рядка в стеку залишились незакриті дужки — послідовність також некоректна.

### 6. Двомовний код (C++20 та Python 3.12)

#### C++20 (`solution.cpp`):
```cpp
#include <iostream>
#include <string>
#include <stack>

using namespace std;

bool is_balanced(const string& s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') {
            st.push(c);
        } else if (c == ')' || c == ']' || c == '}') {
            if (st.empty()) return false;
            char top = st.top();
            st.pop();
            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{')) {
                return false;
            }
        }
    }
    return st.empty();
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);

    string s;
    while (cin >> s) {
        cout << (is_balanced(s) ? "YES\n" : "NO\n");
    }
    return 0;
}
```

#### Python 3.12 (`solution.py`):
```python
import sys

def is_balanced(s: str) -> bool:
    stack = []
    matching = {')': '(', ']': '[', '}': '{'}
    for ch in s:
        if ch in matching.values():
            stack.append(ch)
        elif ch in matching:
            if not stack or stack[-1] != matching[ch]:
                return False
            stack.pop()
    return len(stack) == 0

def main():
    lines = sys.stdin.read().split()
    for s in lines:
        sys.stdout.write("YES\n" if is_balanced(s) else "NO\n")

if __name__ == "__main__":
    main()
```

### 7. Аудит граблів та людських помилок
1. **Виклик `top()` на порожньому стеку:** Призводить до `Runtime Error (SIGSEGV)`. Завжди спочатку перевіряйте `if (st.empty()) return false;`.
2. **Забута фінальна перевірка `st.empty()`:** Для рядків на зразок `(((` алгоритм поверне `YES`, якщо забути перевірити, чи спорожнів стек наприкінці.
3. **Спроба рахувати дужки простими `int count`:** Працює лише для 1 типу дужок `()`. Для багатьох типів `()[]` рахунок лічильниками не ловить перехресні помилки на зразок `([)]`.
