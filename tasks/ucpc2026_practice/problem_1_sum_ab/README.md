# Задача 1: Розминка A + B (Warmup A + B)

**Теги:** `implementation` `math` `long long` `io`

---

## 1. Вдупляння (Sense-Making)

### ELI5 — Пояснення для другокласника 🍎

> Уяви, що у тебе є дві скарбнички з монетками.
> У першій — **A** монет (і монет може бути так багато, що вони не вміщаються в жодне відро у класі).
> У другій — **B** монет.
> Твоє завдання: порахувати, скільки монет усього, якщо скласти обидві скарбнички.
>
> Але є підступ: монет може бути **дуже** багато — більше ніж мільярд мільярдів!
> Тому звичайна «маленька» скринька (32-бітний `int`) лопне. Потрібна велика надміцна скринька — `long long`.

### Формальна умова

| Об'єкти | Операції | Ціль |
|---------|----------|------|
| Два цілих числа $A$ і $B$, $-10^{18} \le A, B \le 10^{18}$ | Додавання | Вивести $A + B$ |

У найпростішій задачі контесту перевіряється:
- базове налаштування середовища (компілятор C++20, інтерпретатор Python 3.12),
- правильне підключення швидкого введення-виведення,
- коректна робота з великими 64-бітними цілими числами.

## 2. Ручні крайові тести

### Тест 1 — Від'ємні екстремуми

**Вхід:**
```
-1000000000000000000 -1000000000000000000
```
**Покрокове міркування:**
1. $A = -10^{18}$, $B = -10^{18}$
2. $A + B = -2 \cdot 10^{18}$
3. Чи вміщається? `long long` зберігає до $-9.22 \cdot 10^{18}$ — так, вміщається.

**Відповідь:**
```
-2000000000000000000
```

---

### Тест 2 — Нулі

**Вхід:**
```
0 0
```
**Покрокове міркування:**
1. $A = 0$, $B = 0$
2. $A + B = 0$

**Відповідь:**
```
0
```

---

### Тест 3 — Великі додатні

**Вхід:**
```
1000000000000000000 1000000000000000000
```
**Покрокове міркування:**
1. $A = 10^{18}$, $B = 10^{18}$
2. $A + B = 2 \cdot 10^{18}$
3. $2 \cdot 10^{18} < 2^{63} - 1 \approx 9.22 \cdot 10^{18}$ — вміщається у `long long`.

**Відповідь:**
```
2000000000000000000
```

## 5. Доведення та Інваріант

### Математичне обґрунтування

Сума двох 64-бітних цілих чисел у діапазоні $[-10^{18}, 10^{18}]$ лежить у межах:

$$A + B \in [-2 \cdot 10^{18},\ 2 \cdot 10^{18}]$$

Знаковий тип `long long` у C++ покриває:

$$[-2^{63},\ 2^{63}-1] = [-9{,}223 \cdot 10^{18},\ 9{,}223 \cdot 10^{18}]$$

Отже $|A + B| \le 2 \cdot 10^{18} < 9.22 \cdot 10^{18}$ — переповнення **неможливе**.
Python використовує довільну точність — переповнення в Python взагалі не існує.

### Псевдокод (мовою людини)

```
1. Зчитати рядок зі стандартного вводу
2. Розбити рядок на два токени: перший → A, другий → B
3. Переконатися, що обидва числа зберігаються як 64-бітні знакові цілі (long long / int у Python)
4. Обчислити суму: S = A + B
5. Вивести S на стандартний вивід, завершивши символом нового рядка
```

### Чому наївний підхід ламається?

> **Наївний підхід:** оголосити змінну як `int` (32-бітна).
>
> Де ламається: при $A = 10^{18}$, `int` містить лише до $\approx 2.1 \cdot 10^9$.
> При записі $10^{18}$ в 32-бітний `int` відбувається **мовчазне переповнення** (undefined behavior у C++),
> результат стає випадковим від'ємним числом → **WA** з першого тесту.

## 6. Двомовний код

### Python 3.12

```python
import sys

def main():
    # Зчитуємо весь ввід одразу — найшвидший спосіб у Python
    tokens = sys.stdin.read().split()
    if not tokens:
        return  # захист від порожнього вводу

    # Python int має довільну точність — переповнення неможливе
    a = int(tokens[0])
    b = int(tokens[1])

    # Виводимо суму; print автоматично додає '\n'
    print(a + b)

if __name__ == "__main__":
    main()
```

### C++20

```cpp
#include <iostream>

using namespace std;

int main() {
    // Відключаємо синхронізацію C/C++ потоків → cin/cout стають ~5x швидшими
    ios_base::sync_with_stdio(false);
    // Відв'язуємо cin від cout → не чистимо буфер перед кожним зчитуванням
    cin.tie(nullptr);

    // long long: 64-бітний знаковий тип, діапазон ≈ ±9.22×10^18
    long long a, b;

    // Перевіряємо успішність зчитування (захист від порожнього вводу)
    if (cin >> a >> b) {
        // '\n' швидше за endl (endl скидає буфер, '\n' — ні)
        cout << a + b << "\n";
    }

    return 0;
}
```

## 7. Аудит граблів та людських помилок

### ❌ Граблі 1: 32-бітний `int` замість `long long`

```cpp
// НЕПРАВИЛЬНО:
int a, b;
cin >> a >> b;
cout << a + b; // переповнення при |A| або |B| > 2.1×10^9
```

💥 **Наслідок:** Undefined Behavior у C++. Компілятор може видати будь-яке число або навіть крашнути. Гарантований **WA** на більшості тестів контесту.

✅ **Правило:** Завжди використовуй `long long` для чисел $> 10^9$. Перевіряй умову задачі: якщо $|x| \le 10^{18}$, то тільки `long long`.

---

### ❌ Граблі 2: Повільний `cin` без `sync_with_stdio(false)`

```cpp
// НЕПРАВИЛЬНО (для задач з великим вводом):
int main() {
    long long a, b;
    cin >> a >> b; // без ios_base::sync_with_stdio(false)
    cout << a + b;
}
```

💥 **Наслідок:** У задачах із тисячами запитів синхронізований `cin` повільний як `scanf`. При великому вводі — **TLE**. Для цієї задачі (один рядок) не критично, але це погана звичка, яка вб'є тебе в задачі 5.

✅ **Правило:** Завжди додавай `ios_base::sync_with_stdio(false); cin.tie(nullptr);` у першому рядку `main()`.

---

### ❌ Граблі 3: Некоректна обробка від'ємних чисел у деяких мовах / реалізаціях

```java
// НЕПРАВИЛЬНО (Java):
int a = scanner.nextInt(); // int — 32-біти, від'ємні великі числа → переповнення
```

```cpp
// НЕПРАВИЛЬНО (C++, unsigned):
unsigned long long a, b; // unsigned не зберігає від'ємні числа!
cin >> a >> b;            // -10^18 зчитається некоректно
```

💥 **Наслідок:** При $A = -10^{18}$ значення інтерпретується як величезне додатне число (wrap-around). Результат — **WA** або **RE** (runtime error при виведенні).

✅ **Правило:** Для знакових чисел завжди використовуй знаковий тип: `long long` (C++), `long` (Java), `int` (Python — необмежена точність).

## 8. Стрес-тест та командна стратегія

### Генератор випадкових тестів (`stress_tester.py`)

```python
import random
import sys

def gen():
    """Генерує випадковий тест для задачі A+B з граничними значеннями."""
    a = random.randint(-10**18, 10**18)
    b = random.randint(-10**18, 10**18)
    print(a, b)

if __name__ == '__main__':
    gen()
```

**Як запустити стрес-тест** (порівняти Python vs C++ на 1000 тестах):
```bash
for i in $(seq 1 1000); do
    python stress_tester.py > tmp_in.txt
    python solution.py < tmp_in.txt > out_py.txt
    ./solution < tmp_in.txt > out_cpp.txt
    diff out_py.txt out_cpp.txt || { echo "РІЗНИЦЯ НА ТЕСТІ $i"; break; }
done
echo "Стрес-тест пройдено!"
```

### Командна стратегія ICPC

| Роль | Дія | Час |
|------|-----|-----|
| **Кодер №1** (найшвидший) | Читає умову, пише та сабмітить A+B | 0–2 хв |
| **Кодер №2** | Читає умову задачі 2, визначає тип | 0–5 хв |
| **Кодер №3** | Читає умови задач 3 та 4, шукає найлегшу | 0–5 хв |

> **Тактика:** Задача A+B — це «безкоштовний балон». Вона має бути закрита до першої хвилини. Поки кодер №1 набирає код, решта команди вже читають наступні задачі. Жодного обговорення A+B на контесті!
